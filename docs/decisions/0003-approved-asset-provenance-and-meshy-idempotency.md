# 0003. Require `ApprovedAsset` SHA-256 manifests at load time and idempotent task ledgers for Meshy generation

## Status

Accepted on 2026-10-22.

## Context

Characters can be generated by AI 3D services (Meshy REST/MCP) or offline scripts. Two failure modes arise if generation and loading are not gated:

1. Retrying a timed-out or interrupted Meshy CLI run without a local task ledger submits a second `POST /v2/text-to-3d` request and bills credits twice for the same character spec.
2. Loading an unvalidated or modified `model.glb` in the browser can introduce missing bone sockets, 24Hz animation tracks, ungrounded meshes or unapproved third-party geometry.

## Decision

Every character directory `chars/<id>/` must carry four provenance records (`asset-spec.yaml`, `generation-task.json`, `asset-manifest.yaml` / `.json`, and the `approval` block inside the manifest):

- **Pre-flight & idempotency (`tools/meshy_adapter.py`):** Validates `asset-spec.yaml` before making any HTTP call (`exit 2` with `0` requests on invalid budget, rig or rights status). Computes `idempotency_key = sha256(canonical_json(spec) + ":meshy-v2")`. If `generation-task.json` exists with a matching key in `PENDING` or `IN_PROGRESS` state, the adapter calls `GET /v2/text-to-3d/{task_id}` instead of `POST`. If the state is `SUBMITTING` with `task_id: null` (crash after write, before response), it stops (`exit 1`) unless `--force-new-task` is passed.
- **Stdlib YAML profile (`tools/yaml_lite.py`):** Parses and serializes `.yaml` files using the Python 3.11+ standard library only, rejecting YAML 1.1 coercion traps (`yes`/`no`/`on`/`off` booleans, sexagesimal numbers, `0.1.0` float coercion, anchors and tabs).
- **Sole approval writer (`tools/approve_char.py`) & load gate (`ModLoader.ts`):** `normalize_char.py` writes `asset-manifest` with `approval.status: "pending"`. Only `approve_char.py` sets `status: "approved"` and computes `manifest_hash` over the RFC 8785 canonical JSON of the manifest (with `approval` omitted). Both `validate_char.py` and `ModLoader.ts` reject any character whose `model.glb` SHA-256 digest or `manifest_hash` disagrees.

## Options considered

- Four-record provenance ledger (`asset-spec.yaml`, `generation-task.json`, `asset-manifest`, `approval`) + stdlib `yaml_lite.py`: accepted. Prevents duplicate Meshy billing, runs under any Python 3.11+ interpreter without `PyYAML`, and detects any post-approval `.glb` or manifest tampering.
- Calling Meshy directly without `generation-task.json`: rejected. Any network timeout or script restart would create duplicate billable generation tasks.
- Depending on `PyYAML` in CLI scripts: rejected. Host inspection showed `PyYAML` is absent in `/opt/homebrew/bin/python3` (`3.13.3`) and Blender's bundled Python (`3.13.13`).
- Including `approval` inside its own `manifest_hash` input: rejected. A hash over a document that contains the hash is self-invalidating.

## Consequences

Replacing `chars/<id>/model.glb` or re-running `POST /api/chars/:id/normalize` resets `approval.status` to `"pending"` until `python3 tools/approve_char.py chars/<id>` is run.

## Soundness boundary

`output.hash` and `manifest_hash` use SHA-256 integrity digests to catch accidental drift, partial writes and unapproved regeneration; they are not a public-key code-signing PKI against a malicious local user with write access to `chars/`.

## Threat model

Protects against accidental credit exhaustion on Meshy retries, YAML 1.1 type-coercion bugs across Python interpreters, and loading unvalidated `.glb` files in the browser.

## Non-goals

- Supporting full YAML 1.2 anchors, aliases, custom tags or block scalars in `yaml_lite.py`.
- Calling the live Meshy network API during automated CI or `npm test`.

## Revisit if

- A second 3D generation provider is added and requires multi-step task graphs in `generation-task.json`.

## Adoption

Implemented in `tools/yaml_lite.py`, `tools/meshy_adapter.py`, `tools/approve_char.py`, `tools/validate_char.py` and `src/engine/ModLoader.ts`.

## Validation

- Done: `tests/meshy_adapter_idempotency.test.ts` and `tools/tests/test_pipeline.py` verified `exit 2` with `0` HTTP calls on invalid `triangle_budget`, `GET`-only recovery on `PENDING` tasks, `0` HTTP calls on `SUCCEEDED` tasks, and fail-closed stop on `SUBMITTING` with `task_id: null`.
- Done: `tests/validate_char.test.ts` verified fail-closed rejection and byte-for-byte preservation on tampered `model.glb`, bad `manifest_hash`, `pending` approval and invalid frame data.
