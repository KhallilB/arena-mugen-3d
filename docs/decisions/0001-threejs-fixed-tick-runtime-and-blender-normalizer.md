# 0001. Use a fixed-60Hz Three.js runtime paired with offline headless Blender 5.2.1 normalization

## Status

Accepted on 2026-10-22.

## Context

`arena-mugen-3d` needs drop-in character folders (`chars/<id>/`) that load without recompiling the engine, a frame-accurate 60Hz combat simulation, and a shared humanoid animation library that works across characters generated by AI 3D tools or built in Blender.

Raw runtime `.glb` retargeting (`THREE.SkeletonUtils.retargetClip`, Unity `glTFast` or Godot `GLTFDocument`) fails when external rigs differ in bone roll axes, rest-pose bind matrices or unit scales. At the same time, variable `requestAnimationFrame` deltas on 120Hz displays break frame-data determinism if passed directly to `AnimationMixer.update(dt)`.

## Decision

Run the combat engine in TypeScript and Three.js `0.186.1` on a fixed 60Hz integer tick (`dt = 1 / 60`), and normalize every character rig offline in headless Blender 5.2.1 (`tools/normalize_char.py`) before the runtime loads it.

- Offline: `tools/normalize_char.py` scales the mesh to `character.json#model.heightMeters`, snaps the lowest vertex to `Y = 0.0`, aligns the 16 canonical bone sockets to `< 5°` twist against `engine_assets/common_anims.glb`, and exports `chars/<id>/model.glb` with all 27 clips baked on Blender frames `0..N` at `scene.render.fps = 60` (`export_optimize_animation_size = False`).
- Runtime: `FighterController` never calls `SkeletonUtils.retargetClip` and never passes variable frame deltas to `AnimationMixer.update`. It restores un-pitched Pass-1 bone quaternions and seeks `mixer.setTime((currentAnimFrame + 0.001) / 60.0)`, followed by three explicit `root.updateMatrixWorld(true)` passes per tick.
- Local editing: a hardened Vite middleware plugin exposes `GET /api/chars`, `PUT /api/chars/:id/:file` and `POST /api/chars/:id/normalize` so the in-game Fighter Factory overlay can save `moveset.json` and `ai.json` back to disk.

## Options considered

- TypeScript + Three.js `r186` fixed-tick runtime + headless Blender 5.2.1 normalizer: accepted. Runs immediately with installed host tools (Node `22.14.0`, Python `3.11+`, Blender `5.2.1 LTS`), supports zero-compile folder drop-in and shares one TypeScript codebase between simulation and the Fighter Factory UI.
- Ikemen GO or unmodified Castagne: rejected. Ikemen GO is 2D sprite-only (`.sff`/`.air`), and Castagne is an Editor-time Godot plugin rather than a runtime `.glb` folder loader.
- Godot 4.3+ with runtime `GLTFDocument` + `RetargetModifier3D`: rejected for the prototype. Godot is not installed on the target host, and its humanoid T-pose silhouette fixer runs inside `EditorSceneFormatImporter`, so runtime `.glb` loading still requires offline Blender normalization.
- Unity 6 (`6000.3.0f1`) with runtime `glTFast`: rejected. `glTFast` imports runtime `.glb` animations as Legacy/Generic and does not compile Mecanim Humanoid muscle curves outside the Unity Editor.

## Consequences

Every new or re-rigged character mesh must run through `tools/normalize_char.py` (`~0.5s` operator time, `~5s` Blender process time) before `tools/validate_char.py` and `ModLoader.ts` will accept it. Editing JSON frame data (`moveset.json`, `ai.json`) does not require re-running Blender.

Because Three.js `r186` `PropertyMixer.apply(accuIndex)` skips `binding.setValue` whenever two consecutive keyframes have identical track values (`accu0 === accu1`), any procedural bone rotation applied after `mixer.setTime` compounds on the next frame unless Pass-1 bone quaternions are restored before `mixer.setTime`. `FighterController.seekBasePosePass1` and `playStateClip` enforce this restore on every tick.

## Soundness boundary

The 60Hz simulation is deterministic within a single JS engine on seeded runs (`tests/state_machine_determinism.test.ts`). Cross-machine rollback netcode across different CPU architectures is outside the prototype scope because IEEE-754 transcendental functions (`Math.sin`, `Math.cos`, `Math.atan2`) are not bit-locked across browsers.

## Threat model

The Vite `/api/chars` middleware runs on `127.0.0.1` during local development. To prevent cross-tab CSRF and filesystem traversal, it validates `:id` against `^[a-z0-9_]{1,48}$`, checks `realpath` containment and exact directory case, rejects symlinks and payloads over `1 MiB`, blocks `model.*` edits on `PUT`, requires `X-Arena-Mugen: 1` and a localhost `Origin` on `POST /normalize`, and serializes Blender runs with a `409` lock.

## Non-goals

- Supporting arbitrary un-normalized `.glb` files at runtime without running `tools/normalize_char.py`.
- Rigid-body ragdoll physics or runtime hip root-motion extraction.

## Revisit if

- `tools/normalize_char.py` exceeds `600` lines of Python or fails to normalize a new character height cleanly.
- The 60Hz tick `p95` frame time approaches the `16.6ms` frame budget (measured `p95 = 0.0912ms` on 2026-10-22).

## Adoption

Implemented in `tools/build_common_anims.py`, `tools/normalize_char.py`, `src/engine/FighterController.ts`, `src/engine/ArenaSimulation.ts` and `vite.config.ts`.

## Validation

- Done: `tests/multi_height_combat.test.ts` recorded `p50 = 0.0286ms`, `p95 = 0.0912ms` (`< 16.6ms`) across `600` combat ticks in `evidence/gate0-frametime.json`.
- Done: `tests/state_machine_determinism.test.ts` verified identical state hashes across repeated 300-tick seeded matches.
- Done: `tests/vite_fs_middleware.test.ts` verified rejection of path traversal, case-insensitive aliases, symlinks, oversized payloads and unauthenticated `/normalize` requests.
